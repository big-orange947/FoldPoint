# 已有付费轨迹的模拟输入诊断

本次只读已有元数据，未调用付费服务。工具按同一会话中有明确 decision/request 对应关系的相邻成功调用统计；成功摘要、无法配对的请求会切断相邻关系，避免把摘要造成的变化误认成普通增长。`afterTokens` 若来自延迟观测，不能当作即时摘要输出长度。缓存读取比例按服务商报告的读取 token 除 prompt token；调用间隔不是服务商缓存 TTL。

| 指标 | 旧固定 60% | v2 动态 |
| --- | ---: | ---: |
| 普通请求 / 无法配对 | 140 / 3 | 140 / 11 |
| 相邻可比较普通调用 | 133 | 117 |
| 宿主上下文增长 P10 / 中位数 / P90 | 16480 / 16481 / 16481 | 16480 / 16481 / 16481 |
| 缓存读取比例 P10 / 中位数 / P90 | 80.0% / 94.7% / 97.0% | 66.8% / 85.9% / 91.7% |
| 摘要成功数 / 缺摘要后长度 | 3 / 0 | 11 / 11 |

两组来自同一类规则化任务、跨批次运行，增长几乎恒定，**不能充当多样日常任务的增长分布**。动态组压缩更频繁，其观察到的缓存读取比例更低；这只是相关性，不能直接推断因果。动态组的摘要后长度为未知，不能从零或摘要输出 token 补造；另有即时反馈文件，但要按明确标识和适用边界核对后才能使用。旧固定组的 after 也可能是摘要后首个请求的延迟上下文。

工具刻意不生成其他策略的反事实轨迹、不预测节费或任务质量。下一步应从有明确顺序和即时反馈的轨迹提取经验输入，再用独立任务检验摘要长度、缓存及成本的预测；已反复分析过的这两组只能作为开发诊断，不能称为留出集。

```powershell
npx tsx tools/trace-workload-audit.ts traces/pi-ledger-1m-paid-fixed-full-01-fixed60.jsonl
npx tsx tools/trace-workload-audit.ts traces/pi-ledger-floor-v2-20261023-full-01-dynamic.jsonl
```

输出包含输入文件哈希和汇总统计，不输出对话或会话标识；非法 UTF-8 或格式损坏的轨迹拒绝分析。
