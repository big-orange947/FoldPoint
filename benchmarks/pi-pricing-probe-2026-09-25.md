# Pi 仓库修复探针：缓存计费回归

日期：2026-09-25。此任务用于检查更接近项目开发的代码工作能否自然产生有意义的
压缩时机比较。它是**人工注入回归**，不是自然发生的生产缺陷；不因任务代码量较大
就预设会发生压缩。

每次运行从同一个 Git HEAD 读取 FoldPoint 的所有已跟踪文件，复制到全新目录，
并仅在 `src/pricing.ts` 注入两个错误：过期缓存按普通输入价而非写入价计费；
缓存存活时漏计输出 token。`node_modules` 从本地、lockfile 匹配的安装复制，
不是指向原仓库的链接，也不在每组之间共享可写目录。需要先在 FoldPoint 原仓库
执行 `npm ci`。任务不使用大型无关文本填充上下文。

Agent 被要求只修改 `src/pricing.ts`。结束后，运行器检查其他所有已跟踪文件的
SHA-256 没有变化，并在不继承 provider key 的子进程中执行 typecheck、全量测试、
build 和工作区外的 [独立 oracle](fixtures/pi-pricing/oracle.test.mjs)。oracle 覆盖
过期缓存、存活缓存和概率混合三种计费。离线自检确认：坏版本不通过；恢复原实现
则通过所有门；改测试文件会被拒绝。

复跑示例（需要已有的 Pi 实验配置和 provider 环境变量）：

```text
npx tsx tools/pi-paired-run.ts --tasks pricing-regression --reps 1 --cache-warming off --out <new-prefix>
```

## 一轮真实 DeepSeek 探针

使用本地 Pi 源码 `d201760ff` 的 bundle、FoldPoint `9d2e793`、DeepSeek
`deepseek-flash`、独立实验配置中的 26K 窗口、`maxTokens=4000`，四组都关闭 Pi
缓存预热。每组只跑一轮；四个 Agent 的工作区、会话和轨迹彼此独立。

| 组别 | 外部质量门 | 普通调用 | 成功压缩 | 未定价失败压缩 | 已观测费用 |
| --- | --- | ---: | ---: | ---: | ---: |
| Pi 默认 | 通过 | 18 | 3 | 2 | $0.026665 |
| 仅提前阈值 | 通过 | 18 | 1 | 7 | $0.024517 |
| 提前阈值 + FoldPoint 否决 | 通过 | 13 | 0 | 0（另有 9 次否决） | $0.011542 |
| 固定晚阈值 | 通过 | 33 | 2 | 0 | $0.040264 |

四组都正常退出、通过未改文件检查、typecheck、全量测试、build 和独立 oracle；
轨迹均以 `session_end` 结束。普通调用的 prompt token 合计分别为 128,587、
153,447、105,473、421,378，说明解题路径并没有保持一致。费用按 Pi 的价格表和
已上报用量估算，未与 provider 账单核对。

**不能把表中的百分比直接当成策略收益。** Pi 的 `session_compact_failed` 事件没有
失败尝试的 token 用量；默认与仅提前阈值组分别有 2、7 次失败，二者的费用只是
已观测费用下界。运行器现在会在成对费用比较中排除涉及这种未定价失败的配对，
而不会把它们冒充完整账单。FoldPoint 对固定晚阈值的配对不存在此缺口，但一轮中
普通调用是 13 对 33、压缩是 0 对 2；模型走了不同路径，仍不能把费用差归因给
动态阈值。固定晚阈值组的调用膨胀也值得单独诊断。

这轮证实了质量门能够在完整仓库修复任务中运作，且 FoldPoint 确实否决了 9 次
宿主阈值检查，未妨碍任务完成。它**没有**证实动态决策比固定晚阈值更省钱或更好。
通用轨迹分析现会输出 `unpricedCompactions`，并在失败尝试提供完整用量或实际费用时
计入成本。用新分析器离线重放本轮四份原始轨迹，得到未定价数 **2、7、0、0**，
与表中一致；没有再次调用 API。现有 Pi 事件无法补出未上报的数据，仍须把相关配对
排除。下一步用多个
不同的真实任务和多轮重复比较；
正常 1M 窗口与 26K 压力窗口必须分别报告。
