# 真实周期预测与执行对账

本次只读上次付费新周期组的轨迹，付费调用0。任务是140阶段受控开发任务；每阶段一次成功普通请求。
以一次摘要后的本阶段普通请求为周期起点，到下一次摘要前的上一阶段为终点，得到10个完整间隔。
第11次摘要之后任务结束，后续没有下一次摘要，该不完整间隔单独排除。

| 指标 | 放行时稳定周期预测均值 | 后续完整间隔实际均值 |
| --- | ---: | ---: |
| 普通调用数/周期 | 11 | 12 |
| 普通输入费用/调用 | $0.00555859 | $0.00601745 |
| 下一次摘要费用/周期 | $0.05831689 | $0.06155664 |
| 普通输入+下一次摘要费用/调用 | $0.01086012 | $0.01114717 |

实际值来自provider用量按当时本地报价计算。普通输出费用未进入周期预测，故为可比性两边均排除；
输出成本仍在审计结果逐周期另列。实际普通请求按token加权的平均缓存命中比例在各周期约85.6%～85.8%。
这里是10个周期各自比例的算术平均85.67%，不是整个会话的总体命中率。

实际输入加摘要约每调用高2.64%；普通输入部分高约8.25%，下一次摘要绝对费用高约5.56%。
12次而非11次摊薄了摘要的每次调用费用，因此不能将两项偏差简单相加。
这些误差说明稳定周期预测与本任务执行有偏差；它们**不证明改掉偏差就能优于60%**，
也不能将跨批次比较中多出的全部费用归因于某一项。

摘要后长度的预测另见 [已发布的真实结果](pi-floor-v2-20261023.md)：11次即时宿主估计平均低估8.88%。
那份数值使用阶段前冻结的评分模型、以实际压缩前长度为条件；本报告比较放行时选择的稳定周期，
两者是不同预测口径。历史固定60%的压缩后长度为离线重建，不能当成当时即时采集。

生长预测为宿主上下文坐标，provider prompt token是另一计量口径；轨迹不能精确拆出每轮新增宿主token，
因此本报告不将二者直接相减充当增长误差。无法观测假如采用另一压缩时机后的真实上下文、缓存及任务表现，
故这里也不提供反事实节费金额。任务终点前最后一个不完整周期不算成完整周期或免费收益。
