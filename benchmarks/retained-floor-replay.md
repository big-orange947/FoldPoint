# v2 总保留率模型：配对合成执行

## 结论

零付费调用。没有修改 Pi、SDK 默认值或冻结控制器，原真实长流0.66%的结论不变。
这次不再比较两种预测世界各自报出的费用，而是让三个隔离时机选择器在**同一实际合成世界**执行：
相同工作量、相同实际压缩器行为、相同缓存与计费规则。

| 对照范围 | 格数 | v2胜/平/负 | v2费用合计相对对照 |
| --- | ---: | ---: | ---: |
| 全部，相对旧仿射模型 | 144 | 27 / 96 / 21 | −0.2571% |
| 全部，相对固定60% | 144 | 99 / 36 / 9 | −7.8455% |
| 长任务，相对旧仿射模型 | 72 | 15 / 42 / 15 | −0.2435% |
| 长任务，相对固定60% | 72 | 67 / 0 / 5 | −8.1257% |

“费用合计相对差”是合成矩阵费用总和之比，受长而贵的场景支配，不是单场景百分比的平均值，
更不是生产使用的预计节费率。格子共享构造参数，不是144份独立真实任务或统计显著性样本。
**相对固定60%的多数优势并非本次修正创造：旧动态模型在这些构造环境中已经有优势。**
本次修正相对旧动态模型的增益很小，且长任务胜负数相同，不能宣称获得了明显升级。

## 执行口径

- 任务长度24、80、240、800次普通调用；240及800归为本报告长任务。
- 平均每次增长5000、15000、50000token，按固定5步扰动序列变化；增长是外部给定的总追加量。
- 缓存读价/输入价0.01、0.1、0.5；输入0.3、输出1.2 USD/M仅为冻结假设报价，不查询当前价格。
- 摘要无共享前缀、共享现存前缀两种合成契约；没有预热。
- 实际压缩器分别采用重叠预算、相加预算两种行为，各自是独立世界。每个世界的三个策略都用同一行为。
- 三个选择器：旧仿射周期、新分段周期、固定60%。两种动态选择器共用50%–70%资格窗口。
- 起点10万token且前缀已暖；普通输出固定300token，计费但不另加到增长里，避免重复计算。
- 动态选择器只看到此前成功调用后已观察到的增长EMA，不知道任务终点或后续增长，也不知道实际保留定律。
- 当前上下文达到70%时强制压缩，保证执行的普通请求不超过该边界；所有策略同样处理。
- 每次成功压缩后普通前缀失效，下一请求重建照常计费；摘要输出也完整计费。
- 不把普通调用减少算作节费：三组在每格的普通调用次数与提供的增长总量完全相同。

这不是原完整控制器的重演：未移植其运行风险门、失败退避和在线学习。
也不模拟真实服务商TTL、摘要失败、模型幻觉或任务质量。真实 Pi 的摘要可能包含多次请求；
本合成压缩器明确每次只有一个请求，因此不能用这里的调用数推断真实 Pi 的摘要费用。

## 回归与复跑

测试覆盖：所有策略提供相同增长、无压缩阶段费用完全一致、任务延长不改变此前动作、
从实际动作独立重算暖缓存读写和摘要费用、保留失败格与平局、不悄悄修改原比较结果。

```powershell
node --import tsx tools/retained-floor-replay.ts --out traces/retained-floor-replay-fresh.json
```

输出路径必须不存在。JSON包含144格三组完整费用与动作，便于检查具体损失场景。
它不会读取key，不调用服务商，不覆盖既有付费实验。

先检查长任务仍输给固定60%的5格：全部位于缓存读价仅为普通输入价1%的暖缓存环境。

这5格中普通请求账单均降低，但多出的摘要费用都超过了普通请求节省。
这是完整账单中的可核对损失面，不是把相似度或无答案率混入了费用。
因此保留长度修正本身没有解决“缓存极便宜时压缩过密”的问题。

下一步继续区分周期边界离散、增长波动、摘要次数或结束时机的影响。
不先调参追求144格全胜；先核对同状态首个分叉、后续实际额外摘要与普通请求节省能否对账。
该诊断通过后，再决定把新模型接入显式启用的Pi实验路径，当前不启动付费长流。
