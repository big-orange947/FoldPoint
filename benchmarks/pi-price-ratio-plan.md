# DeepSeek 执行、价格比例变化：Pi 插件先导试验

本试验只改变模型的**计费元数据**，不更换执行模型。Pi、FoldPoint、任务、
原生压缩器、受控上下文窗口及缓存预热配置保持一致；所有请求仍发给
`deepseek-flash`。因此报告中的假设费用不是 provider 账单，更不是 Claude 实测。

## 预先固定的价格情景

单位是每百万 token 的假设费用（`HYPOTHETICAL`），不是报价。除 `native` 外，所有情景都把
输入固定为 1、输出固定为 5，**只让两个缓存费率变化** —— 因为这两个费率才是结构差异：

| 情景 | 输入 | 输出 | 缓存读 | 缓存写 | 想检验的问题 |
| --- | ---: | ---: | ---: | ---: | --- |
| `native` | Pi 模型表 | Pi 模型表 | Pi 模型表 | Pi 模型表 | 真实 DeepSeek 计费基线（缓存写 **免费**） |
| `cache-read-60` | 1 | 5 | 0.6 | 1.25 | 缓存读取较贵时是否更值得压缩 |
| `cache-write-200` | 1 | 5 | 0.1 | 2 | 压缩后重建缓存较贵时是否应延后压缩 |
| `claude-like` | 1 | 5 | 0.1 | 1.25 | Claude Sonnet 形状（3/15/0.3/3.75，按输入归一） |
| `write-free` | 1 | 5 | 0.1 | 0 | 与 `claude-like` 只差缓存写费率 |
| `write-050` | 1 | 5 | 0.1 | 0.5 | 缓存写费率扫描的中间点 |

**为什么扫缓存写而不是别的**：DeepSeek 的缓存写费率是 0，Claude 是输入价的 1.25 倍。
压缩的本质是"重写一个前缀"，所以在 DeepSeek 上压缩的写入部分是免费的，在 Claude 形
价格下是实打实的支出。这是压缩时机策略最应该反应的差异；输入/输出比例只改变摘要调用
的量级，不改变"什么时候压"的答案。

## 采样控制：`--temperature`

策略对比要求各组的差异来自策略，而不是模型这次走的路径。前几批 cohort 里同一个任务
在不同运行之间用了 18–29 次调用，**运行间方差大于要测的效应**。因此新增 `--temperature`
（写入每次运行的 `models.json` 的 `model.samplingParams`，Pi 会合并进 provider 请求，
见 `packages/ai/src/simple-options.ts`）。

- `--temperature 0`：受控对比，用来分辨 5% 量级的差异；代价是牺牲真实采样。
- 不设置：保持真实采样，只适合大 n 或"看方向"的探索。

两种都必须**在整批内固定**，不能一部分 0 一部分不设。

## 预先登记的预测与反证条件

在跑之前写死，避免事后解释：

- **P1（缓存写免费）**：`native` / `write-free` 下，FoldPoint 相对固定晚阈值应**无优势**
  （配对差落在 ±5% 内）。理由：DeepSeek 的缓存不会失效，"在失效时压"这个机制没有机会
  出手，而"压几次"由阈值决定。
- **P2（缓存写变贵）**：随着缓存写费率从 0 升到 0.5 / 1.25 / 2，FoldPoint 相对固定晚阈值
  的优势应**单调扩大**。理由：写入越贵，"挑一个缓存本来就要重写的时刻压"越值钱，而固定
  阈值看不到缓存状态。
- **反证**：若在缓存写 ≥ 1.25 的情景下，跨 ≥3 个有信息配对（双方都压缩过、费用完整）的
  差值仍落在 ±5% 内，则**动态策略的时机优势未被证明**，诚实结论是"把阈值调晚就够了"，
  而不是"再换一批任务试试"。
- **质量门**：任何一次运行的产物未通过外部 oracle，该配对整对作废，不得用费用便宜的一方
  顶替。零压缩配对、未定价失败压缩配对单独计数（harness 已经强制）。

## 顺序与判定门

1. 零付费单测与 Pi `--list-models` 预检：价格、货币标签、任务质量门和轨迹
   配对正确。失败即停。
2. 先导：`cache-read-60` 情景的一个仓库修复任务，各跑 Pi 默认、FoldPoint
   否决、固定晚阈值一轮。此阶段只验证执行路径和报告。预算由三次任务运行
   与单次 300 秒超时限定，不以假设费用充当真实 API 预算。
3. 若通过，再对**六个情景**（至少含 `write-free` / `claude-like` / `cache-write-200`
   这条缓存写扫描线）、至少三个不同任务做多轮对照，轮换执行顺序，整批固定
   `--temperature`。26K 压力窗口与正常窗口分别报告；短任务作为零压缩负对照。

**真实账单始终是 DeepSeek 的价格** —— 价格覆盖只改变 FoldPoint 与报告看到的数字，
不改变 provider 收费，所以整批扫描的成本仍是每次运行几分钱。假设费用只能用于
情景内部比较，不能与 `native` 组的真实费用相加。

质量失败、轨迹不完整、未定价失败压缩，均不得算为费用胜利。主要结果是
每个情景下 FoldPoint 相比 Pi 默认的完整可计费配对胜率与总费用；固定晚阈值
是必须保留的强基线。零压缩配对单独计数。单轮先导不用于“多数情况下省钱”
或“在 Claude 上有效”的宣传。

PowerShell 下逗号列表须作为一个字符串传给 `npx`，例如：

```powershell
npx tsx tools/pi-paired-run.ts --tasks pricing-regression `
  --conditions 'default,veto,late' --reps 1 `
  --price-scenario cache-read-60 --cache-warming off --out $outPrefix
```

## 先导结果：`cache-read-60`，一轮

2026-09-25 在本地 Pi 0.87.0 bundle、DeepSeek `deepseek-flash`、独立 26K
窗口配置下运行三个策略，每个策略一轮。预检通过；三个独立工作区的仓库
修复任务都通过外部质量门，轨迹均有 `session_end`，且决策记录的价格快照
确为 `HYPOTHETICAL` 的 `1 / 5 / 0.6 / 1.25`。这次执行调用了 DeepSeek，
表中费用则按假设价格重算，**不是实际支付金额**。

| 策略 | 普通调用 | 普通请求 prompt token | 成功压缩 | 未定价失败 | 否决 | 已观测假设费用 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Pi 默认 | 17 | 135,942 | 3 | 4 | 0 | 0.181530 |
| FoldPoint | 22 | 208,222 | 1 | 0 | 15 | 0.178218 |
| 固定晚阈值 | 18 | 156,969 | 1 | 0 | 0 | 0.143837 |

Pi 默认组的 4 次失败压缩缺用量，其费用仅为下界，不能与 FoldPoint 作
严格费用比较。FoldPoint 对固定晚阈值的配对账目完整，但单轮中其假设费用
高约 **23.9%**，普通调用多 4 次，prompt token 也更多。此结果是对
“动态策略在较贵缓存读取下自然更省”的一个**负面先导信号**，不是稳定劣势
的证明；模型解题路径并未保持一致。不能通过事后改变任务或阈值把这轮改写为
胜利。下一步先扩大任务类型和重复数，同时继续保留负面结果与未定价门禁。
