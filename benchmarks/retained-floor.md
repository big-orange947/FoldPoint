# 总保留率与 recent 预算：v2 离线语义检查

本轮没有付费调用，不接管 Pi，不改 SDK 默认值或冻结候选，也不重写旧实验数据。

## 改动

旧先验是 `after = 0.1 × before + 20000`。
若10%表示压缩后的**总长度比例**，就不应该再加一次重叠的recent预算。
本轮研究模型采用 `after = min(before, max(0.1 × before, 20000))`。
recent预算只是保守的预测下界，并非 Pi 一定保留这么多token的承诺。
若接入方给的是“摘要本身比例”，其语义不同，仍可能需要加上独立保留的消息；不能混用。

| 压缩前 | 旧先验 | 新总保留率先验 |
| ---: | ---: | ---: |
| 10000 | 21000 | 10000 |
| 100000 | 30000 | 20000 |
| 250000 | 45000 | 25000 |
| 600000 | 80000 | 60000 |

新模型没有用旧任务的约2.35万长度拟合参数，仍使用原来的10%与2万预算。
它也不保证对所有压缩器都更准确，测试明确覆盖了旧加法语义反而正确的反例。

## 周期公式一起修正

不能把当前长度代入后选一个局部线性分支，再让旧周期算法拿它外推。
令保留率为r、recent预算为B、每次普通调用增长g、周期内普通调用数n，
稳定周期必须同时满足：

`before = after + n × g`

`after = max(r × before, B)`

解为 `after = max(B, r × n × g / (1-r))`。
实现直接逐n求解，复用原有完整计费函数，摘要、摘要输出、前缀重建和可选预热全部计费。
保留旧的256次周期上限；没有可用周期就返回不可用，不偷偷拉长预测范围。

## 离线检查

结构回归覆盖5种比例、4种预算、3种增长速度，逐周期核对解析解与独立迭代递推。
另外逐调用加总核对缓存读价比0.01、0.1、1下的费用，包含摘要共享前缀和独立预热。
纯比例与纯固定预算两种极限下，与旧仿射周期解一致。

32格诊断：4种缓存读价比×4种增长×2种摘要前缀假设。
在共同50万～70万比较窗口下，24格有周期，8格不可用——增长1000时256次上限不足以到达50万。
24格中16格新边界更早、8格相同，没有更晚的格。
但**全部可用格的新边界都是50万**：这是比较窗口下界主导，不能宣传成新算法发现了50%最优。
该窗口只用于受控比较，不是新增的 Pi 配置。

因此报告还保留去掉50万下界的诊断。例如增长15000、摘要无共享前缀时：

| 缓存读价/输入价 | 旧无下界预测边界 | 新无下界预测边界 |
| ---: | ---: | ---: |
| 0.01 | 322222 | 200000 |
| 0.1 | 122222 | 110000 |
| 0.5 | 72222 | 65000 |
| 1 | 72222 | 65000 |

这些只是**暖缓存无限稳定周期的预测**，没有应用实际运行风险门、任务长度或执行资格检查。
新模型可能更早选择周期，不代表压缩次数必然更少，更不代表有限任务账单必然降低。
不同预测世界的费用不能相减当作实测收益。
