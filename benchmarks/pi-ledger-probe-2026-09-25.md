# Pi 真实代码任务探针：账单汇总修复

日期：2026-09-25。目标是检验上一轮“逐行抄录”之外的任务质量，而不是预设一定会发生压缩。

## 任务与质量门

四组策略沿用 [固定晚阈值试验](pi-fixed-late-2026-09-24.md) 的本地 Pi 0.87.0、
DeepSeek `deepseek-flash`、受控 26K 窗口、同一原生压缩器和关闭的缓存预热。每组各跑
**一轮探针**，工作目录与会话独立。Agent 读取 `SPEC.md` 和一个有意包含多种错误的
`ledger.mjs`，修复按用户汇总交易的函数。

复跑时在独立临时目录准备 `PI_CODING_AGENT_DIR`（其中的 `models.json` 使用上轮记录的
26K 窗口覆盖）和 `PI_SCRATCH`，然后设置 `PI_CLI` 指向 Pi 的 bundle；旧版系统 Node
可用 `PI_NODE` 指向 Node ≥22.19。提供有效的 provider key 后执行：

```text
npx tsx tools/pi-paired-run.ts --tasks ledger --reps 1 --cache-warming off --out <new-prefix>
```

脚本不会覆盖已存在的结果文件；不要把真实 key 写入实验目录或命令行。复跑会产生
真实 API 费用。该任务的 fixture 由运行器从仓库复制到每组独立工作目录，不需要
在 `PI_SCRATCH` 预放 `big.txt`。

质量不是通过查找某个字符串判定：运行器在任务结束后另起进程，执行仓库中、未放入
Agent 工作目录的 [5 项 oracle 测试](fixtures/pi-ledger/oracle.test.mjs)，涵盖退款符号、
重复交易 ID、半开时间区间、输出顺序与输入不可变性。它也校验工作目录中的规格文件
没有被改动。初始实现 5/5 测试失败；独立单测验证正确修复能 5/5 通过。测试子进程
不继承 provider key 或任意 `NODE_OPTIONS`。这仍不是恶意代码的完整沙箱，应只在
受信任的本地实验环境运行。

四组的轨迹均完整，费用根据 provider 返回的 token 用量和 Pi 价格表估算，未与账单
核对。**四组都没有触发压缩，所以费用差异绝不能算作压缩策略的收益。** Agent 走了
不同调用路径；一轮探针更没有统计说服力。这个任务作为短代码任务的负对照保留：它
表明现实工作中有些任务无需任何压缩，此时 FoldPoint 不应制造收益叙事。
成对比较器现已将这种双方零压缩的配对标为“不具备压缩时机比较意义”，不计入策略
费用变化；原始费用仍保留在逐组表中，供审计与预算核对。

下一步需要更长、异质且由独立测试验证的代码任务。不能用无意义文本填充上下文来
强迫压缩；如果在正常 1M 窗口下依然不压缩，就诚实地报告“此任务不适用”。若测试
目标是缓存预热，应另外选择具有已验证缓存 TTL 的模型，并把预热开关分层比较。
