# 阈值周期对照实验：有限任务仍亏损

本轮新增独立研究函数，将候选与固定60%放在同一拟合模型和计费条件下，分别迭代阈值周期，
以实际跨阈值的离散调用次数计费。任一阈值周期超出模型已观测范围，回退固定60%；
候选预测平均费用不低于基线时也回退。安全线仍优先。该函数未接管Pi或SDK默认策略。

这一步只修正比较口径：旧研究选择器用稳定周期单点选择，未直接核对固定60%的阈值周期。
两个预测使用相同模型、增长与账单规则，包含摘要费用和缓存重建；普通输出对两侧相同而不影响比较。
它依然假设长期重复周期，预测误差、真实缓存变化和未来任务结束都无法被消除。

在上轮宽跨度历史合成实验中，挑选先前3个输给固定60%的场景作回归，不作为独立测试集：
160次调用、每次平均增长6000、缓存读价/输入价0.02，实际保留规律分别为常量、比例、仿射。

| 实际保留规律 | 固定60%费用／摘要数 | 原支持范围策略 | 新比较门策略 |
| --- | ---: | ---: | ---: |
| 常量 | 0.819594／1 | 0.911116／2 | 0.911116／2 |
| 比例 | 0.828773／1 | 0.918204／2 | 0.918204／2 |
| 仿射 | 0.833247／1 | 0.919951／2 | 0.919951／2 |

数字是合成USD报价单位，并非真实API账单。三格里新门仍预计较早周期长期更便宜，
但本次任务在第二次摘要后结束，实际多出的摘要没有足够后续调用回本。
**本实验没有证明节费改善，不应推广。** 这也不证明有限任务一定都应选择60%。

下一步需要检查可观测的当前runtime剩余工作风险如何与长期周期收益结合，
使用多种事先固定的任务长度、增长和缓存条件做前序测试；不能让策略读取真实终点，
也不能只针对这3格修改。随后再用真实Pi影子数据验证覆盖度与成本预测。
本轮付费调用0，历史真实负结果不变。
