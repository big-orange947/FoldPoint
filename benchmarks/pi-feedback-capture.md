# 原生 Pi SDK 反馈采集：一次小规模真实运行

这次只验证事件和用量采集链路，不比较动态策略、固定阈值或任务质量。
模型是本地 Pi 配置 `deepseek/deepseek-flash`；不是独立核实的服务端版本号。
配置窗口保留 1M，但实际请求只有数千 tokens，**不是 1M 长任务测试**。

## 实测结果

| 请求 | 普通输入 | 缓存读取 | 输出 |
| --- | ---: | ---: | ---: |
| 压缩前普通请求 | 3,417 | 0 | 1 |
| Pi 原生摘要 | 2,681 | 256 | 717 |
| 压缩后首个请求 | 1,390 | 128 | 1 |
| 第二个后续请求 | 256 | 1,280 | 1 |

实际 HTTP 4 次，provider 报告合计 10,128 tokens，没有未对账 HTTP。
本地 Pi 目录价格折算约 US$0.003197184，其中摘要约 US$0.001666236。
**目录价格不是已核实的实时供应商报价或账单**，也不是完整时机策略成本对照。

9 项采集检查全部通过。压缩前宿主长度估计为 3,554；Pi 原生压缩记录的
`tokensBefore` 为 3,418。压缩立即返回的 `estimatedTokensAfter` 为 1,474，
但 `getContextUsage()` 仍为 null。首个后续请求 provider 输入为 1,518；再下一轮
宿主上下文估计为 1,532。摘要输出则是 717。这里几个不同来源的数字不能互换。

采集工具通过 Pi `createAgentSession` SDK 接入完整 `context` 事件链，
只替换 provider 传输以做预算限制和用量记录。单独构造 `AgentSession` 的旧 smoke
只覆盖其原本的生命周期/空闲调度断言，不能据此证明 SDK 的全部 context 接线。

## 旁路模型结论

精确反馈合格样本 0，模型保持 unavailable，没有产生经济预测或接管压缩。
一次压缩本来就不足以识别 affine 模型；更重要的是，宿主估计和后续完整 prompt
不是同口径、无新增内容的压缩前后实测值。不能为了拟合出模型而放宽这条要求。

## 复现与溯源

默认离线运行：

```powershell
npm run capture:pi-feedback -- --out traces/pi-feedback-offline-NEW
```

付费采集需要显式 `--live` 与同一终端的 `DEEPSEEK_API_KEY`，输出目录必须不存在。
HTTP 上限 4；累计请求体上限 200,000 bytes（输入规划代理，不是精确 token 预算）；
普通输出上限 128，摘要上限 2,048。SDK 缓存预热在独立配置中关闭，工具为空，自动压缩关闭，
由测试主动调用一次原生压缩。若 Pi 选择 split-turn 而需要额外摘要，仍遵守总调用上限；
超限或截断视为不完整，不伪装为成功，也不自动加钱重跑。

公开数字见 [元数据结果](reports/pi-feedback-capture-result.json)。运行基线 `6627a0e`，
实际运行的未提交采集源码随后原样归档在 `a4ffff5`，SHA-256 为
`92b11ab075868e1fb773bcb2888a76732f7c229e2db63965503234a8d44d6b3b`。
之后的格式整理和错误用量修订没有重跑这次付费实验；不能把新源码误称为该次 producer。
Pi 提交为 `d201760ffee16564aa8d9a759e0c85b70db33674`。

原始元数据报告和轨迹保存在本地忽略目录 `traces/pi-feedback-live-01/`，公开结果保留两者指纹，
不公开会话标识和运行时间。没有记录对话正文、摘要正文、请求 headers 或 key。
任务质量没有评分；小规模手动采集成功不代表默认算法更省钱。
