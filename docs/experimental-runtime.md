# 实验：当前 runtime 的继续概率

这是显式 opt-in 的研究接口，**没有改变 `FoldPoint.decide()` 默认行为，也没有接管 Pi 插件**。不额外调用模型，不读取正文、密钥或环境变量。

## 实验性压缩固定项预测

### 历史复用与首压账单归因

`new ExperimentalCompactorLearner(history)` 可导入最多 32 条此前成功压缩的观测，
`exportObservations()` 返回只含四个已校验数值字段的副本。未知字段不保留；导入导出
均不共享可变对象。宿主负责持久化与兼容性：压缩器/提示词版本、受保护前缀、
tokenizer、价格制度或币种变化后，不能无条件沿用旧观测。
它不自动识别兼容性，也不读取当前任务终点、正文、缓存或剩余调用数。

`npm run simulate:history` 用固定配方的两次此前合成任务（seed 601、85 次调用、
固定 25%/60%）采集实际反馈，之后在独立评测任务使用：冷启动、只预热 token 模型、
同时预热核心保留率/输出统计，以及固定 60% 对照。当前任务会话计数和 duration age
保持从零开始，不继承缓存或 horizon。核心预热通过已有 observation/state API 完成，
不是改变核心默认值。历史按已知同一合成压缩器分组，这是控制实验的假设，
并非生产中可以按未来真实 floor 选择历史；前缀变化可能让历史不再适用。

历史采集账单单独保留。暖启动比较假设已有这些历史，不把采集成本藏掉，也不建议
为了收集样本额外花钱强制压缩。全部评测组合为已见回归，不称新的盲测。
各策略按相同分界轮（固定 60% 首次成功压缩轮）拆早期/后期账单，摘要费用和普通
调用费用均计入；两部分差额相加为总差额，但不是独立的首压因果实验。

本轮历史复用没有稳定消除固定底座场景亏损；部分价格改善，部分恶化。
早期账单较低可能仅意味着尚未付摘要费，后段差额也包含首压造成的路径变化。
因此不能继续把冷启动误差当作主要亏损解释。下一步应先用可手算的重复周期费用
核对有限 NOW/WAIT 的选择，区分剩余调用分布与周期费用目标的问题；不因看过成绩
就放宽风险/余量，或给某种价格配置设专用阈值。

### 预测与执行门的一致性

研究参数 `executionConstraints` 必须来自宿主实际配置，包含是否已有压缩尝试、
最少普通调用间隔、最小回收 token/比例以及 soft-window token 边界。当前调用间隔
读取核心决策的 `callsSinceLastAttempt`。每个假设压缩重置计数，之后普通调用递增；
NOW 与 WAIT 都应用这些规则，安全 FORCE 绕过经济冷却和最低回收门。
未传该选项时保留原实验路径，默认核心/Pi 行为不变。

这还不是完整递归模拟：未来压缩假设成功，未来学习状态不更新，回收量使用当时的
预测模型，而实际核心的当前资格门仍使用它的比例估计。宿主中断、不安全工具边界、
增长波动和真实缓存行为也不由这个选项预测。不能称为精确最优策略。

`npm run simulate:execution` 保留旧策略、固定 60% 和一致性候选的账单，全部 24 个
组合都是已见回归场景，不宣称新的盲测。额外诊断只在成功压缩结束后结算：
冷启动（不足三次）、低跨度回退、拟合区间内、区间外外推。
分别统计预测长度与摘要费用的有符号/绝对相对误差；KEEP 点没有真实压缩结果，
因此这是所执行压缩的误差，而不是全部时机的无偏校准。诊断不反馈策略。

`ExperimentalCompactorLearner` 为每个兼容压缩器单独创建，只接收已完成的成功压缩：
`beforeTokens`、`afterTokens`、`outputTokens`、`summaryInputCostPerToken`。
最后一项由宿主用本次摘要账单扣除摘要输出费用，再除以压缩前长度计算；单位是
当前价格配置的货币/token。这里仍假设输入费用近似按长度增长，不能混用模型、
缓存制度或不同币种的历史观测。失败不提供压缩结果样本，失败费用仍由既有账本统计。

最近最多 32 条样本中，至少三条且输入跨度达到最大输入的 20% 才拟合：
`after = min(before, a * before + b)`、`output = c * before + d`，系数非负。
固定项是观测的仿射近似，**不是最小观测值就证明了不可压缩底座**，也不是假定
实际压缩器真的线性。相同输入重复压缩不能区分比例和固定项，因而回退原比例预测。
压力路径加最大观测残差，保留既有保留率压力；这不是统计置信区间。
区间外外推、分段 floor、压缩器漂移及摘要输入计费变化仍可能失准。

宿主将 `snapshot()` 放入显式研究参数 `compactorTokenModel`。重复压缩、立即损失与
缓存重建都采用相应预测，真实分支仍按实际输出计费。该选项不修改安全边界、
默认核心或 Pi 接线。本轮只隔离修改预测模型，时机余量与继续概率设置不改。

`npm run simulate:compactor` 的主对照固定 60%，保留旧比例策略及全部亏损案例。
24 个暖缓存场景 × 八组冻结价格比例，其中八个新固定项组合首次运行后即为已见数据。
原报告保留，不能把不同固定阈值的旧百分比直接与本轮数字比较。
固定项场景中过度压缩显著减少，但部分平均费用与胜率恶化；下一步应先校验
压缩预测误差、冷启动与低跨度回退，以及未来重复路径是否正确模拟宿主的资格/冷却门，
不能通过删掉亏损场景或调回激进比例宣称胜利。任务质量仍未验证。

## 分布，而不是确定的剩余次数

宿主传入 `continuationProbability=q`，表示一次普通任务模型调用后，当前 runtime 继续下一次调用的概率。当前调用权重为 1，第 i 个后续调用权重为 q^i。摘要、预热请求不计为普通调用；未来用户的新指令不在这个模型内。

三个预测路径都按相同权重计费：NOW 在当前调用前支付摘要及重建成本；WAIT-FORCE 保留上下文，到增长预测的安全边界时支付较大摘要及重建成本；WAIT-ONE 先付当前请求费用，只有 runtime 继续才在下一次请求前付摘要与重建费用。NOW 必须胜过可行等待路径中较便宜的方案。下一轮真实决策重新使用观测，不提前预约或强制下一次经济压缩。WAIT-ONE 是一阶延后选项，不是完整 Bellman 最优控制或预测信息增益。

WAIT-ONE 的额外风险也要符合下一次估计请求的损失比例与剩余 runtime 预算；到达安全边界的强制压缩不受经济预算阻止。路径内部还会计入再次到达安全边界后的压缩，不能让 NOW 永远享受一个固定的小前缀。普通输出在各路径完全相同的假设下相消。

使用核心已有的保留率、摘要用量、缓存覆盖、存活概率、增长和安全边界指标。假设未来增长保持近期估计，摘要费用与输入长度线性缩放，后续前缀覆盖保持学习比例。这些假设可能失真；与真实 provider 缓存行为、摘要质量都不是等价模型。

每个路径最多 64 次（可显式设置 1–256），每次决定最多计算六个路径（含压力检查），复杂度 O(maxCalls)。q^maxCalls 是被截断的尾部存续概率，显式返回。超过 5% 时拒绝经济触发，不把未建模的尾部当作已经结束。5% 是实验性的计算截断守卫，不是质量或成本保证。仍可能漏掉低概率高代价事件。

## 结束损失和压力检查

立刻结束的额外费用 = max(0, 摘要费用 + 首次重建费用 − 当前直接请求费用)。宿主必须显式提供 `maxImmediateLossRatio`，预算 = 当前直接请求费用 × 该比例。它不是账户限额，也不是实际损失硬保证：估计错误时真实费用仍可能超出。

实验策略要求名义收益与压力收益都超过 `savingMarginRatio × 摘要费用`，同时名义/压力下的立刻结束损失都不超预算。压力情形默认 q 减少 0.05、保留率增加 0.05。这里不再把旧单点 horizon 的完整摘要风险惩罚混用进分布比较；摘要已经在两条路径各自计费。压力参数仍待验证，没有根据获胜场景反向调参。

安全 FORCE、宿主禁用、idle、非安全边界、冷却和最低回收门不被实验接口覆盖。调用者必须传入同一输入刚生成的核心 baseline decision；返回值只是一份研究估计，并不自行压缩或修改状态。

## 累计风险账本

`RuntimeRiskBudget` 是每个 runtime 独立的估计风险账本。宿主显式给预算，在决定前通过 `remainingRuntimeLossBudget` 传剩余额度；未传则不启用累计门，仅保留单次门，用于诊断对照。不得把过去花掉的钱当作已回本，也不得通过想象的未来收益补充额度。

成功经济压缩消耗本次名义/压力立即结束损失的较大者；已发出但失败的摘要消耗真实观测费用。仅在派发或结算时扣款，多次只读查询不重复扣款。安全 FORCE 不扣经济预算，也不被其阻止。失败或估计误差导致超支时应如实展示 `overBudget`，而不是截断 spent 隐藏费用。新 runtime 使用新账本，核心状态格式没有改变。

本轮 benchmark 用首个请求的估计输入重放费用乘显式比例 1/3 初始化固定预算，不随后根据累计历史费用增加。这个参考尺度只是敏感性设置，不是生产推荐值。即使账本没有超预算，真实费用相对另一个策略仍可能超出：账本是估计立即结束风险之和，不是实际 regret、账户限额或任务质量保证。

累计门是宿主可选项，不要求每次压缩都回本。v3 的长任务分组显示严格累计门会牺牲持续运行时的费用收益，因此继续保留不加累计门的 `cacheAwareNoBudget` 候选，而不是用最坏结束风险否定长任务优势。单次立即结束损失比例、压力检查、安全/冷却门仍然存在。

## 压缩频率与费用拆分

`npm run simulate:frequency` 保留同一批 351 个 1M 合成场景，不改变策略或概率。
报告见 [compaction-frequency.md](../benchmarks/compaction-frequency.md)，明细包含每次成功压缩
的步骤、最短/中位间隔，以及四项互不重复的费用：全部摘要尝试、压缩后首次普通输入、
其余普通输入、普通输出。首次普通输入是完整账单，不是相对 KEEP 的额外缓存损失；不得
在总费用之外再加一次。无缓存折扣时不发明 cache-write 溢价，失败摘要也必须计费。

140 调用组每种缓存各 36 个案例，不加累计门的分支：暖缓存 346 次压缩（平均 9.61 次），
持续冷缓存 1241 次（34.47 次），中途转冷 800 次（22.22 次）。相对 fixed60 的逐场景平均
费用变化分别是 −14.91%、−72.34%、−61.17%；摘要费用仍分别占总费用约 28.72%、26.31%、
28.22%。这是按固定假设对 v3 数据的诊断拆分，不是新算法改善，也不能外推真实流量。

累计风险比例 1 的暖缓存长任务为 12 胜/24 负、平均 +2.27%；更少摘要不自动等于更低总费用。
不能因为结束风险而把累计门强制设为默认，也不能因为冷缓存费用下降而声称频繁摘要不会
损伤信息。接下来需要对同一个压缩器、同一任务输入验证信息保留与任务完成情况；没有
质量测量前，不依据该表新增固定频率特判、宣称多数真实任务省钱，或替换 Pi 默认策略。

## 宿主确认前缀连续性

可选输入 `reusablePrefixTokens` 表示：宿主确认本次请求中这些领先 token 与此前发送的内容一致。它是可缓存候选，不是服务端已报告的 `cachedTokens`。明确的服务端用量优先；TTL/过期/缓存禁用继续生效。宿主改写、截断消息或切换前缀时应重新校验并报告 0，不能只因为总长度增长就声称前缀一致。无法确认时省略，保留原有统计估计。

提供连续性信息时，后续成本按追加型上下文预测：当前请求写回的整个上下文可以成为下一次的候选前缀；旧请求的缓存命中比例不再限制新写回前缀的长度。仍通过存活概率估计缓存是否保留；这不是服务端驱逐/块对齐/共享缓存的保证。后续若发生改写，下次实际决策须重新校验，不延续旧声明。

模拟器的 append-only 分支只使用自己上一请求的 token 长度，成功压缩后先清除旧前缀，再由后续普通请求更新；没有读取未来缓存命中、未来闲置时间或任务终点。新字段也进入 TraceInput；不含正文。没有该字段时核心行为不变，Pi 适配器尚未自动声明连续性。

## 校准契约

### 差分时机余量（显式实验）

`savingMarginBasis: "timing"` 要求 `rolloutMode: "renewal"` 且启用 WAIT-ONE。如果下一轮
压缩可行，收益余量尺度改为 `当前请求重放费用 + 一轮增长 × 摘要每 token 费用`；否则
回退到整次摘要费用。余量比例仍由 savingMarginRatio 决定（实验保留 0.1）。完整路径
仍计入每次摘要及缓存重建，不删除共同成本，也不更改 q、压力、立即损失或累计预算。
返回 requiredSaving 与 savingMarginCostScale 便于审计。

这个尺度是针对“什么时候做同一笔投资”的局部不确定性余量，不是概率置信区间。
不能把它理解成摘要一定会做、一定不丢信息或实际 regret 有上限。模型错误仍可能亏损。

`simulate:timing` 保留旧 durationMixture 和固定 50/60/70，原来已看过的数据都作回归；
八个新比例保留组合首次验证以及八个 floor-stress 组合分别报告。为减小文件只保存实际
比较的五个分支，未删案例、负结果或比较者账单。报告格式投影可用 --format-existing
只做机械重排，不重新仿真、不改数字。

成本按摘要、首次重建输入、其他普通输入、普通输出四项独立结算。新 floor-stress 只
修改真实 compactor：after=max(比例×before, 底座) 且不超过 before，output=max(比例
×before, 最低输出)。底座 20k/50k、输出下限 2k，不提前交给策略；通过 recordCompaction
观察反馈。实际不缩短的摘要仍计费；实际及反事实溢出恢复遵守同一规则。旧 fixture 的
底座和最低输出为零，旧报告不重写。

结果：普通新组合对冻结固定阈值，多数价格 8/8 获益；带底座后均为 4/8，Sonnet 1h
平均 +1.47%、最坏 +24.50%。频繁小压缩在固定保留底座/输出开销下不再同样划算。
这暴露了只学习保留率/输出率的局限，不证明真实 Pi 具有这些确定值。尚未验证真实摘要
质量，不能上线；下一步应研究从多次实际压缩观测识别比例项与固定项，而非读取 fixture
底座或给某模型硬编码百分比。

### 显式混合持续时间模型（研究接口）

可传 `durationModel: { completedCalls, components }`，每个成分包含正 `weight` 和小于 1 的
`continuationProbability`。调用者必须提供先验；库没有自动推荐的短/长任务比例。给定本轮
已经存活到第 n 个普通调用边界，后验成分权重正比于 `weight × q^n`，未来第 k 轮的存活
概率是 `Σ posteriorWeight × q^k`，不是把本次 q 平均以后再取 k 次方。

纯函数 `estimateRuntimeDuration` 使用 log-space 归一化，处理长历史下的下溢；它返回完整
条件存活曲线、后验与包含本次的预计调用数。后验变化只在混合先验正确时有意义，不能
因为任务已经运行很久，就不依赖先验地断定它还会继续。单个几何成分仍是无记忆的。

混合模式的概率压力检查将 `probabilityStress` 的质量移向最短成分，保留各成分 q；默认
0.05 即移走 5% 后验质量。与旧模式的 q 减 0.05 不同，不能把两种压力结果当作完全相同
的契约。保留率压力与既有资格、风险、截断尾部门不变。预计路径逐轮使用条件存活质量，
未来风险预算用剩余存活质量之和计算，不把整个未来压成一个固定 q。

宿主负责普通调用计数：摘要、预热、重试和只读 decide 不算；新 runtime 重置。
模拟器在普通 onRequest 后增加年龄，端点只用于事后计分。另设 `frozenDuration` 对照，
将年龄固定为零但使用同样先验、压力规则与 256 调用上限，区分条件更新和仅延长计算窗口。

`npm run simulate:duration` 固定研究先验：80% 的 q=0.8 成分、20% 的 q=0.98 成分，未用
测试终点训练或按供应商改参。0 次时预计 14 次，足够长历史后趋向 50 次；这些是模型
假设，不是真实 Agent 的实测持续时间。旧验证集现在标 seen-regression，另外八个新组合
是首次验证，不能看过之后继续调参并称盲测。逐调用 Brier 单列，不等同于完整概率校准。

本轮暖缓存 140 调用组：Sonnet 5m 从相对 fixed60 +1.73% 改善到 −7.75%，但只有 6/12
获胜，压缩从 70 次增至 194 次；Gemini Flash 为 −6.29%，只有 5/12 获胜。固定零年龄及
固定 q 的 256 调用对照没有相同改善，支持继续研究条件更新，但不证明已达到稳定收益。
新组合对开发集冻结 fixed50 的 Sonnet 5m 平均仅 −1.02%，最坏 +14.62%；部分价格仍平均
更贵。任务质量未测，不能直接上线，也不能把增多的摘要视为无害。旧报告完整保留。

`RuntimeContinuationLearner` 需要显式先验概率与权重，不发明默认剩余次数。完整 runtime 有 n 次普通任务调用，贡献 n−1 个继续样本和 1 个结束样本；右删失 runtime 只贡献确实观察到的 n−1 个继续样本。0 次调用不产生结束样本。调用者负责排除摘要/预热、去重 runtime，隔离不兼容的宿主/模型/工作负载。

这学习的是调用边界上的继续频率，不是任务进度，也不是当前 runtime 的确定终点。长任务贡献更多边界，任务混合变化会导致偏差。校准必须只用训练集，留出会话不可反向更新先验后再评分。

本轮模拟只使用预先列出的 q=0.8/0.95/0.99 和损失比例 1/3 做敏感性检查，**未校准，也不选择默认值**。不把场景的 steps、未来闲置时间或真实压缩保留率提供给实验策略。

## 运行与解释

### Opt-in 多周期重复边界与结束风险实验

`rolloutMode: "renewal"` 在压缩后估计状态到安全边界之间生成最多 16 个重复压缩边界，
NOW 和 WAIT 使用相同的候选族，计入各自的重复摘要和重建费用。NOW 的压力计算使用其
名义选中的同一个边界，不能换一个更有利的压力策略。WAIT 对照包含延后一轮和安全路径。
每次调用最多预测 64 轮（仍可用 maxCalls 修改既有上限）；这不是完整递归策略或精确最优解，
未来经济预测可显式提供 `executionConstraints` 模拟宿主冷却与最低回收门，但仍不是未来逐轮重新求解的完整递归策略。

### 摘要缓存与独立预热的计费契约

`cycleBilling` 仅用于 opt-in 实验，必须同时提供 `compactorTokenModel` 以独立预测摘要输出。
`summarySharedPrefixRatio` 未提供时按历史摘要输入单价计费；显式提供 0–1 时，按该比例
估算摘要请求与已缓存前缀的共享量，并使用 `costOfCall` 计缓存读取、尾部和失效后的写入。
它不是根据供应商或模型名称猜出的命中率；摘要与普通请求还必须采用同一价格契约。
不同摘要提示词可能完全无法复用普通调用的缓存。共享比例不描述摘要造成的缓存替换，
本实验假设 provider 允许独立前缀共存；若宿主不是这样，不能直接使用此预测。

`prewarmOutputTokens` 未提供时不发明额外请求；提供时每次压缩都计一次独立预热的
前缀写入及输出，之后普通请求读取这个新前缀，不再重复计第二次写入。无缓存折扣时，
预热和普通请求各按普通输入收费。预测即刻风险、未来重复费用与收益余量均采用该契约。
目前假设预热成功且之后缓存存活，失败/过期必须另行验证。

`npm run simulate:cycles` 是有限预测之外的稳态诊断：根据过去成功反馈的仿射模型
求稳定 n 调用循环，并迭代阈值循环以保留增长跨阈值造成的长短周期交替。总费用除以
普通工作调用数，不能将摘要/预热的额外请求放入分母制造便宜结果。普通输出设为零，
摘要和预热输出仍计费；不是完整任务账单。无终点、无失败、缓存一直存活等假设下，
参考费用可能低于固定 60%，但仍须用实际逐轮决策的长任务模拟证明能够兑现。

完整任务 simulator 现在支持显式 `Scenario.cycleBilling`。这是一份已知 provider
计费契约，而非压缩器真实保留量；实验策略必须使用相同的 `runtimeSurvival.cycleBilling`。
失败摘要照常计费，不预热、不改变原缓存；成功后可产生一次独立预热，然后普通请求读缓存。
预热回调与普通调用分开，不增加 runtime 的已完成工作轮次或制造一次零增长观察。
实际摘要费与未打折的输入单价独立反馈，不能将缓存后的账单/token 再乘一次缓存折扣。

`npm run simulate:cycle-execution` 保存 96 组实际逐轮决策的完整任务账单、摘要与预热
次数、等待原因、最长连续等待起止证据、压缩点和增长指纹，主对照固定 60%。普通输出
不再省略。与周期参考的理想稳态目标不同，长任务实际费用仍有负结果。
预测中选出的重复边界属于假想 NOW 后的周期，而非当前必须执行的阈值；观察到连续
等待不等于已经证明 bug。应进一步验证预测的未来经济压缩与实际逐轮收益/压力门一致。
默认核心与 Pi 插件、旧付费与合成结果均不变。

### 单周期资格消融（未采用为默认）

`forecastPaybackGate: "single-cycle"` 是额外的保守实验假设：只算到 KEEP 下一次
安全压缩前，当前与预测中的经济压缩都须覆盖摘要、重建、独立预热费用和收益余量。
用存活概率闭式折现未来请求的缓存节省；当前拒绝的 NOW 仍保留完整反事实账单，
不能把未执行候选的摘要费用删掉来制造收益。安全 FORCE 不受此门限制。

这不是全任务省钱的数学必要条件，也不完整复用当前 NOW/WAIT 收益门。
`cyclePayback` 提供周期长度、名义/压力收益及余量；`forecastPaybackBlocks` 只统计
选中 NOW 预测路径的阻拦，不等于实际压缩数。报告 `cycleRejections` 则统计实际
eligible KEEP 决策中本项资格未通过的次数，两者不可混用。

`npm run simulate:forecast-payback` 保留 96 组长任务和 63 组短任务的旧控制。
摘要不命中缓存时，Sonnet 5m 相对固定 60% 的平均节省从 12.63% 降为 3.11%，
Gemini Flash 从 12.44% 降为 3.51%；Flash 仍未稳定获胜。假设摘要共享缓存的
短任务也有新增损失。因此不采用此候选作为默认：跨周期收益不应被单周期截断。
后续应验证有界、多周期的共同策略评估，保持摘要/预热完整计费，不通过新增短视门
掩盖预测与执行差异。上述均为冻结价格下已见合成任务，无真实任务质量证明。

### 名义策略配对压力检查（细节）

显式设置 `stressWaitSelection: "paired-policy"` 后，WAIT 与 NOW 一样，先按名义
费用选择策略，再在压力情景中评估同一个策略。保留 WAIT 的首压类型与重复边界，
不是冻结每个未来压缩的绝对时间；压力下增长后的状态和执行门仍会影响实际触发。
`stressWaitPolicy` 暴露选定 WAIT 的名义/压力账单、独立优化压力 WAIT 的包络费用和
压力 NOW 费用，可以复算 `stressedSaving`，而不把两个不同策略当成同一个策略。

未设置时保留旧行为：WAIT 在压力情景里重新挑最便宜分支，是更保守的包络比较。
新选项是比较语义的实验变化，不是账本错误修复，也不是对所有 WAIT 策略的最坏情形
保证。名义费用、继续概率、压力幅度、收益余量、立即损失和执行资格均未改变。

`npm run simulate:paired-stress` 保留完整旧控制，核对同增长/价格/历史账单，再比较
新候选。部分价格比例下费用和连续等待改善，DeepSeek Flash/Opus 仍不能稳定获胜。
短任务费用未新增，但旧损失仍在。预测中的未来经济压缩只通过部分风险/执行门，
尚未完整复用当前收益/压力门：这轮没有解决完整递归预测一致性，不应据此切换 Pi。

`endingRiskMode: "survival-weighted"` 必须显式提供 `endingLossBudgetRatio`（0–1），
以预计 WAIT 的运行费用为预算尺度，评估 max((1−q)×立即损失, (1−q_stress)×压力立即损失)。
它与默认最坏立即损失门不同，不能声称限制了实际最大亏损，也不是所有可能结束时刻的
累计 regret。未来重复经济触发用剩余几何调用质量乘该状态 KEEP 费用作预算近似。
累计账本仍保留全额损失预算与派发扣款，不被这个选项放宽；安全和资格门也不变。

`npm run simulate:warm` 比较旧策略、多周期严格风险、多周期加权风险、固定 50/60/70。
固定阈值只在开发暖缓存上按总模拟费用选一次，然后冻结在新组合上。该新组合包含新 seed、
长度、增长、保留率，但不是独立真实任务；已看过结果，不应在反复调参后继续称盲测。
报告保留负结果与每轮正收益/压力收益/风险阻拦计数，不读取未来步骤数或真实保留率。

本轮 q=0.95 暖缓存长任务没有改善。加权门虽已不阻拦这些案例，压力收益门仍拒绝了
多数经济候选；不能把立即结束风险门继续当作全部亏损的解释。固定几何 q=0.95 具有
无记忆性，未来调用质量约为 20 次，压力 q=0.9 约为 10 次；这说明持续时间模型值得另行
验证，但尚未证明修改它就能改善真实任务。默认算法与 Pi 适配器未变。

执行 `npm run simulate:runtime`：324 个原始 1M 场景 + 27 个接近触发点后结束的对抗场景，九个独立分支，同一 offered growth 流。额外的 forceOnlyV1 / waitOneNoBudget / cacheAwareNoBudget 用于归因等待路径、费用校准与累计预算，不能删除更便宜的旧候选只保留胜过固定阈值的比较。每一对比较独立排除两侧均无压缩的场景，另按 12/60/140 次调用分组展示费用/压缩次数。结果在 [实验报告](../benchmarks/runtime-survival.md)。零网络/付费调用，不读取 key。已有付费结果和原 324 场景报告不重写。

近结束样本的 midpoint 失效时间现在按该样本实际步数设置，而不是沿用原 12 步样本的第 6 步。新增策略外的 pre-decision replay 费用审计，使用模拟器真实缓存状态校验估计；诊断数值不反馈给决策，不能冒充真实 provider 用量。

便宜缓存不代表一定晚压；引入继续概率也不代表一定合理早压。应同时检查总成本、最坏损失、首压利用率、压缩次数和未回本次数。若频繁压缩带来漂亮成本数字，仍不能证明任务质量没下降。此实验不是真实任务质量测试，不能直接用作发布的省钱宣传。

首轮 force-only q=0.95/损失比例 1 在主矩阵产生 7,003 次经济压缩，1,808 次在现有 shadow 区间未回本。v2 相同 q 和单次损失比例、增加 WAIT-ONE 与 runtime 比例 1 后，变为 1,153 次经济压缩、60 次区间未回本；主矩阵相对 fixed60 平均费用变化 −20.54%，219 胜/105 负。这些是合成场景的等权平均，不是任务质量成绩。较原频繁压缩候选更贵的结果也在报告中保留。

v2 所有 324 个场景仍然首次压缩低于 20% 利用率，近结束组最坏额外费用约 105.5%。审计定位到冷启动后本次缓存预测偏差：某失败样本第二次 KEEP 估计 0.583，而模拟缓存状态计价 0.022165，高估约 26.3 倍。v3 显式前缀连续性在同一例子中将输入估计修正为 0.022165，所有缓存感知样本的 pre-decision 输入价格与模拟计价对齐；旧偏差对照仍保留。这个校准不证明未来概率或真实 provider 缓存行为准确。

v3 的 140 调用组，不加累计门的 q95 候选相对 fixed60 为 96 胜/12 负、平均相对变化 −49.48%；累计比例 1 为 58 胜/50 负、−19.82%。最坏增支分别约 6.69%/15.57%。频繁压缩仍可能降低真实任务质量，这些数字仅支持继续研究长任务收益，不是发布宣传结论。下一步应验证前缀契约的真实宿主接线、摘要次数与任务质量，不必追求每次压缩都回本。
