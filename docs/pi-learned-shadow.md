# Pi 即时反馈影子接口

`adapters/pi/learned-shadow.ts` 是仓库内的宿主/RPC桥接工厂，不是自动加载的Pi扩展。
本轮只完成接口与契约测试，**未在真实Pi进程内执行此新桥接，也没有付费调用**。

本地Pi的 `session_compact` 事件只有compactionEntry等字段，不含即时压缩后长度。
因此不能订阅这个事件后，把下一次context长度直接当即时样本。
宿主需在成功且未中止的RPC `compaction_end.result` 可用时，显式调用 `observeImmediate`。
返回字段的真实性和压缩器/估算器版本绑定由宿主负责，不是字符串source本身能认证的。

接口顺序：

1. `createPiLearnedShadow` 通过同步 `loadHistory` 重播同一绑定、同一顺序流的完整反馈日志。
2. 请求前调用 `evaluate`，传入数值型上下文、增长、报价、账单模型和研究边界。
3. 成功摘要返回后调用 `observeImmediate(result, {sequence, stage})`。
4. `appendFeedback` 同步持久化白名单数字；`writeEvaluation` 同步记录支持范围与回退原因。

两种输出都没有正文。影子返回始终 `applied=false`、`canDrivePolicy=false`；
不注册事件、不调用compact、不返回cancel，也不能把recommendation直接当Pi事件返回值。

历史不兼容/损坏、存储失败或评估失败会禁用此实例的后续影子评估，
返回固定原因而不是回显原异常；它不应改变宿主的原生压缩或任务执行。
已学习但未成功写入的状态也会被禁用，不假装内存与磁盘一致。
回调目前仅支持同步I/O；异步宿主需自行先完成事务后再交接，不能传入fire-and-forget回调。

日志最多重播4096条，超过限制明确阻断，不静默截取末尾32条。
学习器内部仍只保留32条；完整重播用于重现漂移重置与顺序状态。
宿主需要自行规划显式日志轮换和新的流序号，不能把跨会话重置为1的序号直接拼接。
这只是有界研究实现，尚无自动持久化迁移或多进程协调。

测试验证数值反馈保存/重载后学习和建议一致、旧序号不重复写入、缺即时长度不学习、
不兼容历史不偷偷清空成冷启动，以及写入失败不再输出正常建议。
这不证明真实Pi接线、磁盘崩溃一致性、性能或节费。

下一步是在零付费的本地真实Pi/RPC生命周期中挂接本接口，核对实际即时字段、
先评估后学习的顺序和会话重启；通过之前不启用真实控制或付费长流。
