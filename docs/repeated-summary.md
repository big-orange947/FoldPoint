# 重复摘要证据保留测试

本测试只检验公开日志中的关键事实、后续更正与简单前置条件是否还能回答。
**它不是动态时机算法闭环、真实 Agent 任务成功率、1M 试验或整段成本对照。**

## 冻结计划

- 源矩阵版本 `8c054cc`，报告提交 `6995402`，源报告以 SHA-256 校验。
- 源案例：Sonnet 5m **价格配置**、22k 增长/20k 保留底座、seed 151、120 次普通调用。
  这只是时间表来源，不表示本轮调用了 Claude。
- 预先选择其前 90 步：候选摘要在 0/15/22/29/37/45/53/60/68/76/84，fixed60 在 27/52/77。
- 三个组用同一个 DeepSeek 配置。检查点为 29/59/89，每点十二个字段。
  完整历史组不做摘要，只回答探针；探针回答不回灌给后续摘要。
- 计划 14 次摘要 + 9 次检查 = 23 次模型调用，HTTP 硬上限 24。
  累计输入规划上限 1,500,000 bytes（按 token 计价仅是保守预算代理，不是 tokenizer 保证），
  摘要输出上限每次 13,107 tokens，答案上限 512 tokens。

旧约束仅在初始日志出现，后面包含窗口更正、build 替换、测试修复、批准、配置文件
路径更正与备份验证。期望答案由评分器单独生成，不作为模型上下文输入。

## 如何运行

在仓库目录执行。以下命令默认 **不联网、不读 key、不产生质量分数**：

```powershell
npm run quality:repeated
```

确实要真实调用时，在**同一个 PowerShell** 中预先配置 `DEEPSEEK_API_KEY`，并明确
加 `--live`。输出目录必须不存在；以下 `NEW` 应换成新的运行名：

```powershell
npx tsx tools/pi-summary-quality.mjs --profile repeated --live --out traces/repeated-summary-live-NEW
npx tsx tools/repeated-summary-report.ts traces/repeated-summary-live-NEW/report.json
```

`--pi` 可指定本地 Pi 根目录，默认 `D:/pi`。测试直接使用该版本 Pi 的原生初始/更新摘要
提示词，不接管真实 Agent 循环，也不模拟 Pi 的完整 cut point 或 recent-tail 处理。
本次本地 Pi 为 `d201760ff`；记录的是 Pi 配置 ID，而非独立核实的服务端模型版本。

目录中的 `report.json` 保留元数据、评分与用量，不写 prompt、摘要正文或 key。
这些仍是运行日志，应按日志保护。目录价格折算不代表已核实的实时供应商账单。
摘要请求的 `cacheRetention: none` 参数也不保证服务端零缓存命中，实际命中看 usage。

## 比较规则

分析器只接受完成的真实三组运行。缺探针、重复探针、改过的冻结计划、未知/截断用量
或预算超限均不能作为完整证据。完整历史参考若未通过，`comparisonReady` 为 false。
该字段只表示具备比较条件，不表示候选已经通过；候选的逐字段退化单独列出，不能
靠总分相抵。离线 fake 运行和截断注入测试都不打质量分。

## 本轮结果与限制

三组均为 3/3 检查点完全正确、36/36 字段正确。实际 23 HTTP、218,155 provider tokens，
无未对账 HTTP。目录价格折算约 US$0.087993，只含摘要与探针，不含正常 Agent 请求，
**不能据此比较两个时机策略的整段费用**。

候选摘要调用输出用量从 427 增至 5,183 tokens，fixed60 从 628 增至 973。这是 provider
用量，不是独立测量的摘要文本 tokens 或压缩后上下文大小（也未单独记录推理 token 拆分）。
覆盖的日志内容也在增长，不能仅凭此确定增长原因；但不能忽略它、或默认输出固定为 2k。
因为时间表冻结，本轮没有把这些实际长度反馈给时机算法后重新决策。

一个公开日志、一个模型配置、每组一次运行，不构成统计非劣性证明。接下来应在较少
真实任务上验证闭环反馈、摘要增长和最终任务结果；不应为这次成绩修改通用保留率或
按模型名称特判。默认核心和 Pi 策略均未改变。
